Design Implications
Cross-Cutting Principles
Six design principles derived from the persona research that should guide every navigation and dashboard decision.
PRINCIPLE 01
Role-Aware Navigation
Navigation should adapt to the user's role and primary jobs — not expose every feature equally. A recruiter's nav is not a compliance officer's nav.
Aisha Priya Marcus Rachel
PRINCIPLE 02
Trust Through Transparency
Partners need to see behind the numbers. Attribution trails, payout timelines, and real-time data aren't features — they're trust signals.
Jordan Sade David Elena
PRINCIPLE 03
Persistent Quick Actions
Every persona has 1-2 actions they do constantly. These must be accessible from anywhere — not buried in a workflow that requires 4+ clicks.
View partner card Copy tracking link API health status
PRINCIPLE 04
Eliminate the Toggle Tax
Multi-program brands lose context every time they switch. The default view must be portfolio-wide. Program drilling should be opt-in, not required.
Aisha Rachel Marcus
PRINCIPLE 05
Progressive Data Density
Different users need different data densities. Cards for Sade, tables for David, executive summaries for Rachel. Same data, different presentations.
Sade — cards David — tables Rachel — exec
PRINCIPLE 06
Proactive Over Reactive
The system should surface issues before users hunt for them. Smart alerts, anomaly detection, and at-risk flags turn passive dashboards into active assistants.
Anomaly alerts Fraud flags API health
