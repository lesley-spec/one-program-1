# Reporting Mock Generator

A Figma plugin that drops realistic reporting mocks onto your canvas: a chart and a data table, styled against your team's **Styleguide V2** library in **Vnext** mode.

## What it does

- **Chart section** — pick a chart type from a recharts-style list (`LineChart`, `BarChart`, `AreaChart`, `PieChart`, `ScatterChart`, `ComposedChart`, `RadarChart`, `RadialBarChart`, `Treemap`, `Funnel`, `Sankey`). The plugin draws a **native Figma vector** version of that chart (no images, no runtime recharts).
- **Data Table section** — define your own columns (header text + type) and row count. Three cell types are supported: **Text**, **Dollar**, **Number**. The plugin instantiates the library's Table component and applies the correct variant per column. If the library Table cannot be found, it falls back to a hand-rolled table with the same shape.
- **Vnext mode binding** — the generated frame has the Styleguide V2 variable collection's Vnext mode explicitly set, so every nested token (color, type, spacing, radius) resolves in Vnext.

## Install (dev mode)

```bash
cd figma-plugin
npm install
npm run build
```

Then in Figma desktop:

1. Menu → **Plugins** → **Development** → **Import plugin from manifest…**
2. Pick `figma-plugin/manifest.json`.
3. Run the plugin via Plugins → Development → "Reporting Mock Generator".

## Usage

1. Open a Figma file in a team that has the **Styleguide V2** library enabled (with the **Vnext** variable mode).
2. Run the plugin. The status bar at the bottom will report whether Styleguide V2, Vnext mode, and the Table component were resolved.
3. **Chart** — pick a chart type, optionally tweak series/data-point counts, click **Insert chart**.
4. **Data Table** — set the row count, define each column's header and type (Text / Dollar / Number), click **Insert table**. Use **+ Add column** and the × button to manage columns.

The plugin places the result at the center of the current viewport and selects it.

## How discovery works

- **Styleguide V2** is located by scanning available library variable collections for a name matching `/styleguide\s*v?2/i` (or a local collection with the same name as a fallback).
- **Vnext mode** is the first mode on that collection whose name matches `/vnext|^v?next$/i`.
- **Table component** is resolved in three steps (in order):
  1. If `TABLE_COMPONENT_KEY` is set in [`code.ts`](code.ts), the plugin imports that component directly via `importComponentByKeyAsync` — this is the most reliable path.
  2. Otherwise it scans every page of the current document for a local component or component set whose name matches `/data\s*table/i`, `/^table$/i`, `/table\s*row/i`, or `/table\s*cell/i`.
  3. As a final fallback, it inspects existing instances in the file and grabs the main component of any instance whose name matches the same patterns. This lets the plugin "borrow" the library Table if it has already been used in the file.

The plugin then inspects the component's property definitions to find a cell-type variant property (matched against `/type|variant|cell.?type|data.?type/i`) and a header-flag property (matched against `/header|is.?header/i`), and maps your column types to the appropriate variant values via these hints:

- **Text** → `/^text$/i`, `/^string$/i`, `/label/i`
- **Dollar** → `/dollar/i`, `/currency/i`, `/usd/i`, `/money/i`, `/^\$/`
- **Number** → `/^number$/i`, `/numeric/i`, `/count/i`, `/int/i`, `/\d/`

If your team uses different names, edit the matchers at the top of [`code.ts`](code.ts):

```ts
const STYLEGUIDE_LIBRARY_NAME_MATCHERS = [/styleguide\s*v?2/i, /style\s*guide\s*v?2/i];
const VNEXT_MODE_MATCHERS = [/^v?next$/i, /vnext/i];
const TABLE_COMPONENT_NAME_MATCHERS = [/data\s*table/i, /^table$/i, /table\s*row/i, /table\s*cell/i];
const TABLE_COMPONENT_KEY = ""; // paste a published key here for direct import
```

> The Figma plugin sandbox cannot enumerate every component in every library at runtime — only variable collections are listable. To get the most reliable Table resolution, paste your published Table component key into `TABLE_COMPONENT_KEY`. You can find the key by selecting an instance in Figma and reading `instance.mainComponent.key` from the console, or via a `search_design_system` MCP call.

## File layout

```
figma-plugin/
  manifest.json       Figma plugin manifest
  package.json        npm scripts (build, watch, typecheck)
  tsconfig.json       TypeScript config (outputs to dist/code.js)
  ui.html             Plugin UI (vanilla HTML/CSS/JS)
  code.ts             Sandboxed plugin logic — discovery, chart rendering, table instantiation
  dist/code.js        Build output (generated by `npm run build`)
```

## Notes & limitations

- **Charts are vector approximations**, not pixel-accurate recharts renders. The recharts library is only the menu of shapes; chart drawing is implemented natively against the Figma node API.
- **Colors** for chart series use a small palette baked into the plugin so the output looks usable even when no tokens resolve. The wrapping frame applies Vnext mode, so any tokens referenced by nested components (notably the library Table) resolve in Vnext.
- **The library Table component** must be reachable from the current file. The fallback table is used when the team library is not available, when no component with a matching name is found, or when the file is opened outside a team that publishes the library.
- The plugin runs with `networkAccess: { allowedDomains: ["none"] }` — no network calls.
